# 원작 AI 호출 주기와 구동 구조

기준 빌드: `1a4a447d`(Steam buildid 25953386). RVA 는 따로 적지 않으면 현재 빌드 값이고 `옛` 표기는 `1fbe6be7` 빌드 값이다(변환: AI_TacticsMod/tools/rva_remap.py, rva_map/1fbe6be7_to_1a4a447d/functions.tsv).

## 1. 초기화 `C11E0` (옛 `C0150`) — 확정(코드)

- 문자열 `0000/bt_exce.bin`, `0000/param_s.bin` 을 읽는다(`C11E0`의 `C15D3` 참조, ghidra_full str). 기본판 파일 `0000/bt.bin` 문자열은 이 함수가 참조하지 않는다(13C44E0 문자열은 다른 곳에서 쓰임, 참조 함수 미해결).
- 게임 설정 싱글턴(`3EC1A0`)의 +0x8E0 값으로 두 가지 영역(+0x800 / +0x860)을 골라 엔진에 등록한다.
- 엔진 콜백 등록: `4F90C0`(콜백 A), `C36A0`(**개별 조건 dispatch**, 옛 `C2610`), 설정 13칸 표(마스크·값, rulebase.md 7절).
- AI 관리자 객체(getter `B6F90`, 옛 `B5F00`): +0x30 활성 여부, +0xC0 부터 **1,000,000바이트 판단 문맥 영역**(변수 저장소). 갱신 때마다 0 으로 지운다(REP STOSB).

- 근거: `ghidra_full.py callees 4403E0` 직접 호출 순서(B6F90 x14, C1840, D4DE0, C1790, D4D70, D4E20, 234DE0/2CB6C0, D4D00 ...), 옛 `AI_Analysis/upper/scheduler_callers.json`(옛 43E030 -> D3D50/D3D90/D3C70). REA_Analysis/core_ai.pseudo.cpp 1절과 일치. 분기·skip 조건 전체를 복원한 것은 아니다.
- 변형 `440B30`(옛 `43E780`): 플레이어 군단 확인(330B90, 235300)으로 시작해 `D4D70`(군단), `C0DA0`(군세 문맥), `B28300`(문맥 정리, 옛 B25A50)을 부른다. 옛 분석에서는 군세 `D3D90`·부대 `D3C70` 만 부르는 재판단 전용으로 기록됐고 현재 빌드에서는 군단 판단 호출(`44120F`)이 보인다. **위임 군단(플레이어)용 재판단 변형으로 추정**(미해결).
- 판단 한 번의 안쪽: 각 판단표 진입 함수 `B65D0`(부대, 옛 B5540), `B6A40`(세력, 옛 B59B0), `B6B00`(군세, 옛 B5A70)이 트리 실행 상태기계 `B2EB30/B2E960/B2EA50`(선택/순서/전체검토, 옛 B2C260/B2C090/B2C180)을 구동한다. 군세는 재판단 요청 필드 +0x38 이 켜지면 같은 군세를 최대 10회 다시 실행한다(core_ai.pseudo.cpp 4절, B6B00).

## 4. 날짜 상태기계와의 관계 요약

- 날짜 상태기계 `44DEE0`(옛 `44BCA0`)은 하루 12소단계, 32 case 로 건설·전법 시계·함정·시설 일일 효과 등을 돌린다(lane_L3.md 2절). **판단표(AI) 호출은 이 기계 안에 없다.**
- 따라서 AI 판단은 날짜 기계와 별개의 상태 객체(`COtherStrategyState` 슬롯 5 = `44DD30`)가 진행 단위(세력 턴)마다 작업 큐로 `4403E0` 을 제출하는 구조다(확정, L3b). 세력 판단표가 `일자내부값`(= 일 == 1) 으로 매달 1일에만 대상 재선정을 하는 것이 유일하게 확인된 날짜 연동이다.
