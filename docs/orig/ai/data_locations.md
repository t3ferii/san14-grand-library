# AI 데이터 위치: 판단표·수식·구동 코드가 어디에 있는가

## 1. 판단표 파일 (확정)

| 파일 | 크기 | SHA-256(앞 16) | 노드(세력/군단/군세/부대) | 비고 |
|---|---|---|---|---|
| `0000/bt_exce.bin` | 473468 | `315f16d0f27cf511` | 246 / 10790 / 348 / 111 | **파워업키트 CE 판단표. `C11E0` 가 읽는다(확정).** Steam 25953386 갱신(2026-11-05)으로 군단 트리만 +478 노드 |
| `0000/bt.bin` | 313220 | `90075810eefbd0c0` | 211 / 6781 / 348 / 55 | 기본판 판단표(미사용 확인 안 됨: `C11E0` 는 bt_exce 를 읽음). 세력 트리 id `0x57c83e03` 등 4개 트리 id 는 bt_exce 와 같고 군세 트리는 바이트 동일(해시 `0x9c5b9a81`) |
| `0000/param_s.bin` | 1632 | `e27de8b52f240b9e` | 수식 100개 | 판단표의 `CCallScriptNode` 가 번호로 호출. 이전 분석 시점과 같은 해시 |

- **AI 판단표는 0002 rdb·fixdata 안에 있지 않다.** 게임 폴더의 평문 파일 `0000/*.bin` 이다. 이 폴더의 다른 파일(`Map.bin`, `MapExCe.bin`, `ccscore_data.bin`, `experience_data*.bin`, `effect_info.bin` 등)은 별개 자료다(형식 해독은 다른 문서 몫; 0002 rdb·0005 bin 은 data_formats_archives.md).
- AI 모드(`AI_TacticsMod`)는 이 파일을 쓰지 않는다(소스·문서에서 bt_exce 를 쓰는 곳은 읽기 전용 분석 도구뿐, grep 확인). 판단표는 원본 그대로 쓰이고 모드는 훅으로 판단 함수 일부를 덧씌운다.

## 2. 파일 형식 요약 (확정, REA_Analysis/verify_behavior_trees.py 의 파서와 현재 파일 대조)

```text
JBTP 헤더 (16바이트): "JBTP", 버전 u32=2, 섹션 수 u32=4, 예약 u32=0
섹션 표 (12바이트 x 4, 파일 +0x10부터): { 시작 u32, 길이 u32, 섹션해시 u32 }
각 섹션: ... "KTBT" 트리 헤더: magic, 버전 u32=1, 트리id u32, 예약 u32=0, 노드수 u32
노드 레코드: flags u32 (bit1=문자열 있음, 4/8은 현재 데이터에 없음), kind u32(노드 종류 해시), parent u32(0xFFFFFFFF=루트),
             자식수 u32, 인수 개수 u32, 인수 u32[n], (flags&2이면 길이 u32 + CP932 문자열)
섹션 끝: "IBBG" (노드 레코드 뒤)
```
조건 노드(kind 0x2252b2cb)의 인수 형식: args[0]=전체 NOT, args[1]=전체 AND 여부(0=OR), args[3]=레코드 수, 이어서 레코드 {kind(0=AND 묶음,1=OR 묶음,2=개별), inverse, op, group_count, nargs, args[nargs]}. 묶음 레코드 뒤에 group_count 개의 개별 레코드가 이어진다(core_ai.pseudo.cpp 3절).

## 4. 노드 실행 코드 위치

- 노드 종류별 실행 함수(vtable 16번 칸)는 node_kinds.md 의 "현재 실행 RVA" 열(옛 RVA 를 대응표로 옮김; 대응 상태 열이 `same` 이 아니면 재확인 필요).
- 조건 함수는 conditions.md 의 "현재 RVA" 열. 객체 해석 보조 함수: `BF790`(세력), `BF4C0`(군단), `BFBC0`(칸), `B7210/B7170`(판단 주체), `B28D20/B28BB0/B28C70`(문맥 변수 읽기: 객체/정수/이름).
