## 2. 외교 공통

### 2.1 판정 흐름 (확정, command_audit.md:86)

결과 함수 `1DB900`(Diplomacy 클래스 단계 20) → AI `1408080B0` → 판정 `808930`(외교관 보너스 `806DA0`; 엔진은 중립) → 수락 `326ED0` → 효과 `81F290` → 종류별 효과 함수.
`808930`/`806DA0`은 외교 AI가 성공률(`param_4`)을 종류별 문턱(`141A4BE88`/`94`/`A0`/`AC`/`B8`)으로 1/2 등급으로 바꾸는 **판단** 코드라 복제하지 않는다(command_audit.md:283).

### 2.2 성공률 공통 식 (확정, command_audit.md:88-98)

`성공률 = (제공' − 요구 × 3/10) × 100 / 제공'`
* 제공' = 제공 × (정책 효과 0x17 가산) 이며 종류 4·8은 외교관 개성 효과 0x40 가산도 곱한다. 정책 0x17 항은 개성 배율을 곱하기 전 원값 V에서 구한다: `제공' = V×(100+개성0x40)/100 + max(1, V×정책0x17×1/100)` (S15 정정, command_audit.md:432; 엔진 `resolve_diplomacy`).
* 외교관 정치' = 정치 + 정치 × 개성 0x40 / 100 (`2B50A0`). (r5_research에서 0x40 = 논객, 정책 23 = 종횡술로 부름. r5_research.md:표 친선 4행.)
* 제공 가치 `324320`(종류 4·5·8·9 공통), 첫 비-0 분기만 센다(확정, command_audit.md:430):
  금 > 0 → 금(상수 `141A4B3AC`=100, ÷100); 아니면 군량 > 0 → 군량×10/50(`141A4B3B4`); 아니면 도시 → min(도시 +0x49, 50)×400(`141A4B3BC`); 아니면 무장(최대 3, `26C510` 합); 아니면 지역 → 3000 + 100×지역 +0x68(`141A4B3C4`/`3D0`). 금과 군량을 함께 내도 금만 센다.
* 무장 가치 `26C510`(확정 구조, 2항 APPROX): `((600×#능력≥100 + 180×#≥90 + 20×#≥70 + 100×#(등급 3 개성) + 200[전법에 학습 가능 ID(31..130, >139)가 하나] + 200[정책 +0xA1 bit0: 미구현 APPROX] + 기본 능력 5개 합) × 50) / 10`, 하한 1000(`141A4B3E8`), 개성 효과 0xF 보유 시 +3000(`141A4B400`). 개성 등급 3(`+0xBE==3`)은 trait.json `color==3`로 대응(APPROX).

### 2.3 수락 `326ED0` (확정, command_audit.md:96)

우호도 등급 5(≥100, `2AF940`)면 무조건 성공, 아니면 `roll100 < 성공률`. 이민족 군주가 도시에 있으면 친선은 항상 성공(`808930`).
* 엔진 등급 경계: F ≤ 0 → 0, < 30 → 1, < 50 → 2, < 70 → 3, < 100 → 4, 그 밖 5 (`people.cpp:219`). 원문은 등급 5(≥100)만 기록 — 나머지 경계는 엔진 값(추정).

### 2.4 우호도 (확정, command_audit.md:97, 61-62)

* 변경 지점은 `2719C0` → `25A080` 한 곳. 양쪽 방향 모두 `+= delta`, 각각 0..200으로 자른다(엔진 `Game::friendship_add`, `people.cpp:208`).
* 시간 경과에 따른 자연 변화는 없다. 덤프에서 우호도 변화 총 2,835건(2,179,638 쌍·순)은 전부 이벤트다: +10/+20 친선, −5 동맹 실패·공격 요청, −8 계략 실패, −15 공격 요청, ±30 이상 = 함락·파기·멸망 (command_audit.md:195-216).

* 동맹·외교 기간: 상태 바이트 `+0xEA` 하위 7비트 = 남은 개월, 월 단위로 줄어 만료 시 해제(`2EE080`이 씀)(command_audit.md:63).

## 3. 종류별 외교

### 3.1 친선 4 (확정)

* 요구 `324F20` = `((200−F)² / 8 × k/100) + (100 − 정치'/2) × 상대 도시수`, 50 단위 내림 (command_audit.md:92). 엔진은 k = 100(우호도 0이면 200)(`people.cpp:222`; k의 원문 값은 문서 미기록 → 추정).
* 성공(`823690`): 새 우호도 = `max(10, F + min(잉여×10/(1070−정치'), 40) + int(10×효과8/100))`, 잉여 = 제공 − 요구 (`141A4B210/218/220`). 효과 8은 정책 효과(행위 세력 값이 0이면 대상 세력 값). 이민족 대상이 F < 50이면 상한 `min((F+1)/2 × 제공/1000, 19)`와 바닥 1(`141A4B240`). (command_audit.md:98, `people.cpp:225-226`)
* 이민족 군주가 도시에 있으면 항상 성공. 이민족 교역국 시스템과는 별개 경로(6절).

### 3.2 동맹 5 / 파기 6 (확정)

* 동맹 요구 = `3240F0`(우호 부족: F<100이면 `(100−F)(1070−정치')/10`) + 기간 비용 `(개월−5)×100 + 150×D + 4000`. 엔진은 기간 비용을 `max(4000, …)`로 둔다(r5_research.md 동맹 5행에서 유래, 최근 audit에는 max 표기 없음; 이 값 범위에서는 차이가 사실상 없음). D = 도시수 비교(`ours<theirs ? 2·theirs−ours : theirs`, 엔진 `people.cpp:227`, 정의는 r5에서 옮긴 것 → 추정).
* 성공(`822710`, `2EE080`): 기간 = 남은 개월 + 지정 개월, 최대 48(`2EE080`의 0x30). 우호도는 최소 50으로 올림(`141A4B26C`). 실패 우호도 −5(`141A4B274`). 엔진 지정 개월은 `aux`(0이면 12, 1~48).
* 파기(`8229B0`): 동맹 중에만 가능, 성공률 판정 없음. 관계 해제, 우호도 −50(≥110이면 60으로), 다른 일반 세력 전부와 −5(`141A4B2B8`, 이민족·중립 제외), 평판 −20(엔진에 상태 없음), 그 세력 무장 중 충성 ≤ 100인 비혈연은 `(군주와 주의 같으면 0/다르면 10) + roll(2)` 하락(`141A4B2D8`). (command_audit.md:99-100)
* 세력 평판 = 세력 `+0x1BE`(short, ±1000, `2255F0` 호출 22곳, 단계표 `1413A9DDC`). 무장 공적과 다르다(S15, command_audit.md:457).

### 3.3 항복 권고 7 (판정식과 이전 경로)

* 판정 `3263B0`(S10), 효과 `824090`. 실패 시 우호도 −20(`141A4B37C`).
* 현재 빌드 `3263B0`의 종류 7 분기. 경과일 `G+0x450 > 360`, 인접 판정 `2C9890`, 일반 제3 세력이 하나 이상(46..51과 당사자 제외), 권고하는 쪽의 도시 수 ≥ 4×상대 도시 수, 상대 도시 수 <5, 전체 병력 ≥ 3×상대 병력이 필요하다. 전체 병력은 `2AF5E0(세력,1,0)`으로 거점·부대 병사를 더한다. 상대 군주가 우리 군주 또는 교섭 무장을 혐오하면 실패한다.
* 점수 `S = trunc(정치′ + B + R + (A−D)/5.0 + (A/D)/2.0 − 상성차/7.0)`. `정치′`는 교섭 무장 `2B50A0(무장,3,0x40,1)`의 반환값, `A/D`의 A와 D는 양쪽 도시 수다. `B=10`은 `32EE60`이 반환하는 유효 세력이 상대와 일치할 때, 그 밖에는 0. `R=20`은 상대 군주와 교섭 무장이 배우자 또는 의형제일 때, 그 외에는 상대 군주의 친애 목록에 교섭 무장이 있으면 10, 아니면 0이다.
* 상대 군주의 거점이 속한 지도 영역을 기준으로 양쪽의 유효 부대 병사를 합산한다(부대 현재 지역 `+0x35` 대조, `234DE0`이 참인 부대 제외). `P = max(0, trunc(권고측 영역 병사 / max(1, 상대 영역 병사 + 상대 거점 병사)))`, `T = trunc(P² / D)`. 성공 조건은 `min(T,30) + Y + Rng(Y) ≥ trunc(100 − 우호도/4.0 + 상대 군주 매력/5.0)`, `Y=trunc(S/2.0)`. `Rng(Y)`는 `3269DB → 3FDAF0`의 원작 난수 호출이며 Y<2이면 0이다. 상수는 현재 PE `141A4B5D4..141A4B67C`와 `141345C4C`를 대조했다.
* 성공 결과 `824090`은 `27BB90`로 종국·플레이어 패배 분기를 검사한다. 이 함수가 0을 반환하면 `2A44C0(항복한 세력, 인수 세력, 0)`을 실행한다. 1이면 `32D990` 경로로 간다.
* `2A44C0`은 다른 세력과 항복 세력 양쪽의 우호도 칸을 0으로 만들고 동맹 관련 `2EE080`을 호출한다. 항복 세력이 지키는 도시·관문의 포로(`무장+0xE6=6`)는 `2E9980(무장,1)`으로 풀어준다. 소속 무장의 야전 부대는 조건을 통과하면 `25A880(부대,0,0,0,4)`로 정리한다. 거점은 `26EEB0`으로 인수 세력 직할 군단을 지정하고, 항복 세력이 가진 지도 칸에는 `186E60`으로 인수 세력을 쓴다. 이어 인수 세력 칸에 있는 제3 세력 부대에 적대 조건이 성립하면 그 부대의 세력으로 다시 칠한다.
* 남은 무장은 신분과 `+0x15E` bit14에 따라 `273100` 또는 `266780`으로 처리한다. 신분 검사 `234FF0(무장,6)` 쪽은 충성·상태 필드를 재설정한다. 마지막에 `2956A0(항복한 세력,0,1,0)`으로 세력을 정리한다. 이전 뒤의 무장별 세부 값과 `27BB90=1`의 하위 처리는 추가 확인 대상이다.

### 3.4 포로 반환·교환 8 (확정, command_audit.md:428-434)

### 3.5 공격 요청 9 (확정)

* 효과(`823E50`): 요청받은 세력에 (요청자, 대상 거점, min(동맹 잔여 개월, 12)개월)을 저장, 우호도 `max(50, F−15)`로 한 뒤 추가 −5. 요청 중이면 거절.

### 3.6 교환(0x13, 19)

**명령 종류 확정.** 현재 빌드 RTTI `CCommandExecutionExchangeNode` vtable `134CD78`의 슬롯 16이 `53530`이다. 이 함수는 명령 번호 `0x13`을 써서 `1EE460`에 전달한다. 양쪽 요구·제공 인자의 종류 0은 금, 1은 군량, 4는 명품 객체를 읽는다. 시전 쪽 금·군량은 군주 거점의 보유량과 비교해 부족하면 제출을 거부한다. `CCmdActionDiplomacy` vtable `+0x98`(`1EEE00`)은 명령 `+0x70`을 반환하고, 결과 `81F290`이 0x13을 `824310`으로 넘긴다. 이 연결로 UI 문자열의 명령 개수 추정 없이 교환임을 확인했다.

**플레이어 UI와 명품 확인.** HUD 외교 행 0x2D는 `451550`에서 외교 종류 0x13을 넘긴다. `CStrategyDiplomacyState` 초기화 `72B420`은 0x230바이트의 `CStrategyDiplomacyTradeLayout`(vtable `1442AC0`)을 `state+0x480`에 붙인다. 갱신 `7358D0`은 창의 결과 `+0x180=0xB`에서 `6CE970`을 호출한다. 이 함수는 창의 `+0x198/+0x190`과 교환 자료 `+0x1D8/+0x1E0/+0x1E8` 등을 명령 구조로 옮기고 `1F1000 → 1EE460`으로 검증·등록한다. `7A4600`은 상대 세력 소유 명품 목록에서 `명품+0x4F` bit0을 검사해 명품 선택 노드 0x6E를 켠다. 검증 `1F1000`은 제공 명품의 소유 무장 `+0x4A`도 대조한다. 명품 외에 포로를 다루는 별도 입력이 있으므로 AI 교환 객체 종류 4와 포로 선택을 혼용하지 않는다.


**우호도 효과 `824310`**. 대상이 플레이어인지 `235150`으로 검사한다. 결과가 1이면 컴퓨터 대상에 `max(50, 기존 우호도 −15)`를 적용하고, 플레이어 대상에는 이 분기에서 우호도 쓰기가 없다. 결과가 1이 아니면 대상에 −5를 적용하며, 대상이 플레이어라면 요청 세력 `+0x4C`에 오늘+60일을 쓴다. PE 상수 `141A4B384/390/39C/3A4`와 `8243D7..8244AC`에서 분기·값을 확인했다. 자원·객체 교환 본체는 공통 결과 루틴 `81F290`에 있다. 객체 종류 4의 모든 실제 값과 교환 UI의 세부 입력 경로는 별도 확인이 필요하다.

### 5.2 성공률 공통 꼬리 (확정, command_audit.md:259-262)

`inner = 1 + (Ia ≥ 100 ? 2 (K+/Kdiv)² + 2 Ia/100 : 2 (Ia/120)² + 2 (K+/Kdiv)²)`
`rate = clamp(int(M × sqrt(비용 × inner / 10000) + Kterm), 0, 100)`
* Ia = 시전 무장 지력' (`2B50A0`: 지력 + 지력×개성 0x41/100), K+ = max(K + 세력(정책) 효과 0x42, 0). 지수 1/2(`141A4C000` 등), 기준 100(`141A4C158`), 120.
* 정책(세력) 효과 번호와 개성 효과 번호는 별개 이름공간이다(예: 개성 0x42 = 소속도시 도적 무효, 정책 0x42 = 계략 K 가산)(pre6_tactics.md의 정정 취지, lane_L1.md:66).

| 10 | `−(F(t→s)+수도 지역 치안)×25/100 − (t 군사 지력'+s 군사 지력')×50/100 + 70 + roll(시전 세력 군사 지력'/3) + Ia + eff42` | 70 | 100 | K | roll < 0.7×률 대성공, < 률 성공 |

* **계략 방어 항 `1E0440(순찰 명령, 시전 무장, 계략 종류)`**. 순찰 명령 `+0x40` 값이 0이 아니고, 남은 값 `22BD20`(명령 vt+0xA8 − vt+0xB0, 최소 0)이 `명령+0x75 + 1` 이하여야 한다. 순찰 담당 무장은 명령 `+0x20`의 첫 무장이다. 그의 세력 참모(`세력+0x52`)가 유효하지 않으면 `230390`을 사용한다. `I(x)=2B50A0(x,2,0x41,1)`, `r=3FDAF0(I(참모),1,종류+25,순찰 무장 번호,시전 무장 번호,대상 거점 번호)`. 반환값은 `clamp(trunc((세력 효과 0x44 + trunc((2r+4I(순찰)−I(시전))/15)) / d),0,40)`. 현재 코드의 나눗수 `d`는 0xB=40, 0xC=20, 0xD=3, 0xE=1, 0x14=1, 0x18=10이다. 0x17도 40 분기가 있지만 직접 호출 12곳은 앞 여섯 값만 넘긴다. 상수와 분기는 `1E05CB..1E061C` 및 `141A4BDEC..BE4C`에서 확인했다.
