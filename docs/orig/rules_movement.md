## 5. 하루 이동량

원작 구조(**확정**: fidelity/dump_measurements.md 4차 3절, 5차 1절; pre6_timing.md 4절; worldmap_spec.md:342-345):

```
(상태기계 44DEE0의 case 7·8, 하루 12소단계마다 부대당 1회: 2DC550 -> 2DB9A0)
if (누산기 +0x14 < 다음 칸 비용 BF1B0(지형)):
    누산기 = min(1000, 누산기 + 26AB00)          # 26AB00 = int(100 x 2B2550 / (100 + 2B7BC0))
if (비용 <= 누산기): 한 칸 이동, 누산기 -= 비용
```

- 갱신 횟수 = **12회/일**. 근거: 상태기계 소단계 `iVar5 = 시각/2`(0..11), 추적에서 `2DB9A0` 호출 수/일 ÷ 부대 수 중앙 11.91(P5 9.97, P95 14.32, 838개 순 쌍). **확정**(dump_measurements.md 5차 1절, lane_L3.md 0절).

**정정/충돌 후보**: 조사 목록 R01 칸의 「설정 객체 `3EC1A0` 옵션 표」는 `3EC1A0`이 설정 객체 접근자일 뿐이며 옵션 값은 객체 안 필드(+0xC0 등)·`3EC920(값 객체, id, n)` 배열에 있다. 기존 10절 표의 「거점 발자국」·「칠하기 호출자」 서술과는 충돌하지 않는다(위 표는 추가). 이 절은 **4KB 이상 함수(`42E5A0` 5679B, `42C570` 1584B 포함 `4306B0` 4455B) 판독이라 강한 모델 검토 필요**.

**강한 모델 검토 결과 — 둘러싸임 판정의 극성 (2026-11-25, 지휘 세션, `ghidra_full.py func 42C0F0`·`42D1D0`·`42E5A0`, 확신도: 코드)**:

- **가상 소유**: 세 함수 모두 지역 소유를 `22E650(지역)`으로 읽는다. 다만 문맥 `+0x10`이 바로 그 지역이면 문맥 `+0x18`의 세력을 대신 쓴다. 즉 「방금 소유가 바뀐 지역을 새 소유자 것으로 친」 상태에서 판정한다.
- **출발 후보 `42C0F0(문맥, 지역 R, 세력 p, &목록)`**(621B): R의 소유가 p가 아니면 아무것도 안 한다. p 소유면 R의 이웃 지역(`230C00`)마다 `+0x38` bit 0x40이 꺼져 있고 소유가 p와 적대(`2CC630(p, 소유)`)인 것만 목록에 넣는다.
- **탐색 `42D1D0(문맥, 지역 R, 세력 p, &덩어리, &경계, &방문)`**(949B, 재귀 깊이 우선):

  ```
  R이 이미 방문 목록에 있으면 → 1
  R을 방문 목록에 넣는다
  R의 bit 0x40이 꺼져 있고 소유 ≠ p → 이웃마다 재귀, 하나라도 0이면 → 0
                                        모두 1이면 R을 「덩어리」에 넣고 → 1
  R의 bit 0x40이 켜져 있고 소유 ≠ p → 0          (탈출: 둘러싸이지 않음)
  그 밖(소유 = p)                   → R을 「경계」에 넣고 → 1
  ```

  결론: **p가 아닌 지역들의 연결 덩어리가, bit 0x40 지역에 하나도 닿지 않고 p 소유 지역에만 막혀 있으면 「둘러싸임」**이다. 덩어리 안 지역의 소유가 서로 다른 세력이어도 상관없다(소유 ≠ p만 본다). bit 0x40 지역은 출발 후보에서도 빠지고, p가 아닌 소유이면 탈출구가 되므로 포위점령으로 칠해지지 않는다. bit 0x40을 쓰는 코드는 이번 정규식 검색(`| 0x40`·`& 0xbf`)에서도 안 나왔다. 데이터 적재 때 비트 필드로 들어오는 것으로 보이며 뜻은 여전히 미해결이다(후보: 거점·관문 지역, 지도 가장자리 — 가설).
- **칠하기**(`42E5A0` 줄 446~700): 탐색이 1이면 `42C570`이 덩어리 지역들의 칸을 모으고 `42BDC0`이 대상을 정한다. 덩어리 안에 특정 세력(`local_170`, 줄 531) 소유 지역이 있으면 건너뛴다. 그 밖이면 칸마다 `186E60(지도관리자, 칸, p, …)`로 칠하고 `42A260`으로 기록한다. 거점 칸(지형 15~18)은 그 거점 객체 소유가 p일 때의 번호를 넷째 인수로 넘긴다. `local_170`이 플레이어 세력인지는 미확인이다(X05).
- **새 DLL에 주는 뜻**: 「포위점령 위협」은 지역 그래프에서 계산할 수 있다. 계산 방법: 적 지역 하나를 빼앗았다고 가정한다(문맥 `+0x10/+0x18`과 같은 가상 소유). 그 이웃의 비-자기 덩어리가 bit 0x40 지역에 닿지 않고 닫히는지 같은 깊이 우선 탐색으로 본다. 닫히면 그 점령 하나로 덩어리 전체가 넘어온다. 지역 이웃은 `지역+0x56` u16×8, 사용 비트 `+0x66`이다(ai/roles.md 6-4절 7항).

### 11.1 출진(규칙 부분만; 누구를 어디로는 판단이라 복제하지 않는다)

- 조건: 거점 소유, 출진 무장이 그 거점에서 임무 없음(status 1~4), 병력 ≥ 1,000(`SORTIE_MIN_TROOPS`)이고 ≤ 거점 병력, 군단 명령서 1장, 경로 존재, 목표가 적대(동맹·정전이면 사유 6), 진형은 무장 소유 비트(`1EC890`). 몽충·누선 진형은 격류 통과 경로. 거부는 `CMD_REJECTED`(사유 1 형식·자격, 2 금, 3 명령서, 4~7 출진·수송 세부). 출진 비용: 명령서 1(군단 `+0x14`). **엔진 확정 구현, 원작 전체 자격은 일부 미확정** — fidelity/command_audit.md:217-240 (8절), RULES.md:12-14.
- 출진 부대는 **거점 군량을 가져가지 않는다**(부대는 자기 군량이 없고 연결 부대의 소비는 거점이 순마다 지불, rules_movement_supply.md 4절). 부대 생성 시 칠하기는 부대가 선 칸 1개(`2D53F0`).
- 명령서 수: 군단마다 `min(200, 10 + 중심 칸을 군단 세력이 소유한 지역 수/10 + 정책 효과 37 값)`. `2593E0`(옛 257990)이 매 순 덮어쓰고 `267410`(옛 265A60)이 상한 계산. 덤프 대조 221 군단-순: 정책 37이 없는 70/70 정확, 전체 166/221(나머지는 정책 37 수준이 시간에 따라 +2~+8 자라는 것으로 추정, 미확정). **확정(식) / 정책 37 값 입력 미해결**. fidelity/worldmap_s9.md 2절.
- 원작 AI의 출진 판단 함수는 찾지 못했다(S7). 덤프 출진 통계(신규 출진 1,302 / 작전 513, 투입/수비 중앙 2.0, 승자가 더 큰 세력 81 %, 거점 수 비 중앙 5.2)와 캠페인 규칙(`launch_rule 1`)은 **판단 APPROX** — rules_movement 범위 밖(AI 묶음). 이전 문서의 "180일 재출진·11,000/10,000·잔류 5,000·120%·720일 완화·80 % 주둔"은 코드에 없다(13절).

### 11.3 이민족·도적 이동

이동 규칙 자체(길 찾기·ZOC·점유)는 일반 부대와 같다. 출진 식(`2607E0`, 반응 출진 `2C4D40`, 명령 종료 후 자동 목표 `2FFB00`)과 도적 출현은 [rules_tribes.md](rules_tribes.md) 소관이다. 이 문서에서 필요한 사실만: 이민족·도적(0x2E~0x33)은 병참 연결 면제, 이민족끼리 비적대(APPROX), `tribal_tick`의 15칸 추적은 사용자 관찰(APPROX(user))이며 코드 값(`5 + 굴림(6)`칸)과 충돌(12절).
