# AI와 모더를 위한 모드 호환 규약

## 목적과 범위

각자 모드를 만들면서 훅·설치 파일·설정·UI·저장 자료의 충돌을 미리 드러내고, 향후 모드 매니저가 의존성과 설치·제거 순서를 판단할 수 있게 한다. 이 문서는 기존 AI교정 모드의 모듈 매니페스트와 호환 지침에서 공통 원칙을 추렸다. **범용 모드 매니저와 외부 안정 ABI가 완성되었다는 뜻은 아니다.**

현재 제공하는 공통 매니페스트는 `schema: 1`이다. 기존 AI교정 모드 내부 `module.json`과는 별도 외부 패키지 형식이며 자동 호환한다고 가정하지 않는다. 공통 도구는 선언된 충돌을 정적으로 검사한다. 누락된 훅, 행동 의미·실행 순서·동시성 충돌은 별도 검토와 실게임 확인이 필요하다.

## 모드마다 선언할 것

`examples/example-mod.json`과 `schemas/mod-manifest.schema.json`을 따른다.

- 전역에서 구별되는 `id`(예: `author.mod-name`), 버전, 대상 EXE와 분석 SHA256.
- `depends`: 필수 패키지 id. 버전 범위는 현 규격에서 자동 해석하지 않으므로 별도 notes로 명시한다. `conflicts`: 함께 쓸 수 없는 패키지 id.
- `hooks`: 종류(code/call/vtable), **현재 빌드 RVA**, 실제 교체 길이, 원래 바이트·값을 확인하는 guard의 근거, 불일치 시 해당 기능 중단 정책. vtable은 실제 슬롯의 RVA와 길이 8을 적는다. 함수 시작 주소만 적고 패치 자리를 생략하지 않는다.
- `files`: 게임 설치 폴더 기준 상대 파일 경로. 경로의 대소문자·슬래시 차이는 같은 파일로 본다. EXE·세이브·백업 소유 선언은 금지한다.
- `settings`: 설정 파일, 섹션, 키. `ui`: `author.mod:entry`처럼 구별되는 화면 소유 id. `resources`: 실제 공유 파일·bank·레코드 id를 합친 표준화된 소유 키.
- `provides`·`uses`: 제공·사용 API 이름. 버전은 이름에 넣는다(예: `author.mod.api/v1`). 안정성·등록 시점·스레드·콜백 수명은 해당 API 계약에 적는다.
- `off_behavior`·`uninstall`·`notes`: 기능 OFF, DLL 부재, 제거와 복원, 검증된 조합과 미확인 범위.

## 훅 소유와 체인

한 패치 자리에는 조정된 소유자 하나를 둔다. 원래 바이트 또는 vtable 값이 다르면 무조건 덮어쓰지 않고 해당 기능을 끈다. 체인은 양측이 허용한 자리에서만 합의하고 현재 "다음" 함수를 보존해 호출한다. 자기 훅·원작 주소를 반복 호출하는 순환을 막는다. 선언만 같다고 체인이 안전하다고 판정하지 않는다.

실제 변경 구간이 겹치면 오류다. 서로 다른 패치라도 같은 16바이트 블록을 건드리면 원자 교체 충돌 가능성을 경고한다. 패치가 여러 블록을 걸칠 때도 전체 길이를 비교한다. 서로 다른 빌드의 RVA를 직접 비교하지 않는다.

## 파일·자원·설정·저장

프록시 DLL 이름이 겹치면 설치 순서와 체인·업데이트·제거 규칙을 명시한다. 다른 모드 DLL을 허락 없이 덮어쓰지 않는다. 원본 EXE는 보존한다. UI 아카이브·bank는 변경한 레코드와 자신이 만든 자원만 추적하고, 공유 파일 전체 덮어쓰기와 무조건 원복을 피한다.

다른 모드의 설정 파일·키·로그 이름을 사용하지 않는다. 원작 세이브 형식을 바꾸지 않고 필요 자료는 모드 id·스키마 버전이 있는 별도 sidecar로 관리하는 것을 권장한다. 설치·갱신·제거는 파일 해시와 소유 기록을 확인하고, 다른 프로그램이 수정했으면 멈추고 보고한다. 기존 사용자 파일·백업을 보호한다.

게임 효과는 게임 UI/AI 스레드의 원작 함수 호출 또는 훅으로 만든다. 외부 프로세스 메모리 쓰기·원격 호출을 사용하지 않는다. 기능 OFF·모듈 부재·제거 시 그 기능의 UI·구독·자원을 해제하고 원작 또는 앞서 설치된 모드의 동작으로 돌아가야 한다.

## 정적 충돌 검사

```powershell
.\library.ps1 compat .\examples\example-mod.json .\examples\another-mod.json --json
```

패키지 id·대상 빌드·의존성·순환·명시 충돌·API·설치 파일·설정 키·UI·자원 키·훅 범위·16바이트 블록을 비교한다. exit 0은 선언된 오류가 없다는 뜻이고, 경고는 남을 수 있다. exit 1은 충돌, exit 2는 형식 오류다. 정적 검사 통과를 실게임 호환 보증으로 표시하지 않는다.

## 기존 AI교정 모드와 함께 쓸 때

[AI교정 모드의 호환 지침](https://github.com/t3ferii/san14ce-ai-mod/blob/main/docs/MODDER_COMPAT.md)을 해당 버전 소스와 함께 확인한다. 이 도서관은 그 모드의 최신 설치 상태나 모든 훅을 자동 추적하지 않는다. 현재 버전의 실제 선언을 확보하기 전에는 "호환 확인"으로 표시하지 않는다.

기존 로더의 `dinput8.dll` 자리, 같은 훅·vtable 슬롯과 16바이트 블록, UI `ScreenLayout.rdb`와 모드용 bank를 확인한다. 기존 문서 기준 bank 24~31은 해당 모드가 쓰므로 조정 없이 사용하지 않는다. `SAN14_Layout.dll` API는 외부 모드용 안정 ABI 검증 사례가 아직 없다는 기존 문서의 한계를 유지한다.

우리 프로젝트 내부의 DLL 구성·단일 설정 파일·로깅·설치기 카탈로그 규칙은 그 프로젝트를 수정할 때 적용한다. 독립 모드에 같은 DLL 수나 같은 설정 파일을 강제하지 않는다.
