# 설치 후 대도서관 갱신

공동 조사 문서·조회 도구의 버전과 게임에서 만든 로컬 캐시는 별개입니다. 새 문서가 올라왔다고 원작 캐시를 지우거나 다시 디컴파일하지 않습니다. AI가 예전에 읽은 내용도 자동으로 바뀌지 않으므로 갱신 후 해당 분야 문서를 다시 읽습니다.

## Git clone으로 받은 경우: 업데이트 감지와 반영

아래 명령은 공개 대도서관 checkout에서 실행합니다. 먼저 `git remote -v`로 origin이 이 대도서관인지 확인하고 `git status --short`로 사용자 변경을 확인합니다.

```powershell
git fetch origin
git rev-list --left-right --count HEAD...origin/main
git log --oneline HEAD..origin/main
git diff --stat HEAD..origin/main
```

숫자 두 개는 각각 로컬에만 있는 커밋 수, 원격 main에만 있는 커밋 수입니다. 두 번째가 1 이상이면 아직 받지 않은 원격 변경이 있습니다. fetch 실패는 최신이라는 뜻이 아닙니다. 네트워크·인증 오류를 보고하고 기존 작업본으로 오프라인 조회할 수 있습니다.

깨끗한 main 브랜치에서 첫 번째 수가 0인 경우 다음으로 받습니다.

```powershell
git pull --ff-only origin main
git rev-parse HEAD
```

사용자 변경이나 로컬 전용 커밋·기여 브랜치가 있으면 reset·강제 덮어쓰기를 하지 않습니다. AI가 diff를 보존하고 별도 작업본 또는 해당 브랜치의 병합 절차를 선택합니다. main을 기준으로 버전을 고정한 모드는 임의로 올리지 않고 변경 내용을 먼저 검토합니다. 문서만 바뀌었다면 prepare를 실행할 필요 없이 새 문서를 읽습니다.

## 자동 설치본(ZIP)으로 받은 경우

현재 bootstrap은 Git 이력 없는 소스 작업본을 받습니다. **설치본의 Git commit 자동 기록, 전용 업데이트 확인 명령, 백그라운드 알림은 아직 없습니다.** `library.ps1 status`는 캐시 상태이며 공개 문서가 최신이라는 뜻이 아닙니다. [최신 변경 이력](https://github.com/t3ferii/san14-grand-library/commits/main/)에서 새 변경을 확인할 수 있으나, 설치 버전 기록이 없으면 현재 설치본과의 정확한 차이를 자동 판정할 수 없습니다.

최신판으로 갱신하려면 README의 최초 두 줄을 다시 실행합니다. bootstrap이 최신 공개 소스를 별도 작업본으로 받고 마지막에 `Library source:` 경로를 출력합니다. 이후 AI와 조회 명령은 **그 새 경로**를 사용해야 합니다. 이전 폴더에서 prepare만 실행하면 원격 문서는 내려받지 않습니다. 개인 수정은 자동 병합하지 않으므로 기존 폴더는 보존하고 새 문서와 비교합니다.

사용자 지정 `-CacheRoot`·`-GamePath`가 있었다면 bootstrap에도 같은 값을 전달합니다. 다른 캐시 경로를 사용하면 기존 캐시를 못 찾아 새로 준비할 수 있습니다. 게임 해시와 캐시 생성 recipe가 같고 검증을 통과하면 `[cached] ready; no download or analysis needed`로 기존 캐시를 재사용합니다. 이때 소스 ZIP 다운로드와 캐시 검증은 발생합니다. 게임 빌드·분석 의존성·추출 스크립트 등 생성 조건이 달라지면 캐시 준비가 필요할 수 있으며 지원하지 않는 게임판은 중단합니다. 소스 업데이트 성공과 캐시 재검증 성공은 구분합니다.

## AI에게 맡길 문장

```text
설치된 삼14 대도서관의 공개 문서 업데이트를 확인하고 최신판으로 갱신해 줘.
docs/UPDATING.md를 읽고 Git/ZIP 설치 방식을 먼저 구분해 줘.
내 수정과 기존 캐시는 보존하고, 같은 생성 조건의 캐시는 재사용해 줘.
실제 적용된 소스 경로와 확인 가능한 버전, 캐시 재사용 여부를 보고해 줘.
버전을 확인할 수 없거나 네트워크가 실패하면 최신이라고 단정하지 마.
```
